# Vivreal_Site_Migrator: knowledge digest

**Using this skill.** It is loaded into the caller's own context; there is no expert agent to dispatch. Cite file:line at the deploy line's SHA for anything you act on, and re-derive any count or roster from source before you rely on it.

Source of truth: `Vivreal_Site_Migrator` `CLAUDE.md` (and the docs it links) at `origin/master`.

Last synced: 2026-10-28 at `origin/master` `dfbfdd3` (deployed line is `origin/master`; this repo has NO GitHub Actions, so a push triggers nothing; per-skill baseline in vivreal-skills `scripts/skill-sources.json`)

Agent-driven repo with **three modes**: `/migrate` (migrate an external site's content into the Vivreal CMS, 1:1 data/structure parity), `/template` (turn an exemplar site into a reusable renderer identity kit: the exemplar's design grammar copied faithfully, while content, nav words, section order and brand facts are the kit's own, owner decision 2026-10-14), and **live-site restyles** (restyle an ALREADY-LIVE site in place, see the restyle section). The repo is the **orchestrator only**, renderer components live in the renderer repo; net-new components are authored there via the template track's `component-builder` agent, never as migrator code. Read `CLAUDE.md` at `origin/master` first (committed 2026-09-25); `docs/migration-flow.md` + `docs/template-flow.md` carry the detail. The agents are no longer in this repo's `.claude/agents/` (moved 2026-10-06, #73): they are the **`vivreal-site-migrator` plugin** in the vivreal-skills marketplace, the five stage agents (`ingest`, `collections`, `integrations`, `site`, the USER-GATED `cutover`), the template-era trio (`kit-designer`, `component-builder`, `page-confirm`), `studio-confirm` (the editability authority), `studio-registrar` (portal-side palette/editor/whitelist registration) and `migration-estimator`, plus the `/migrate` and `/template` commands. The loader is extracted into `packages/site-loader`, installable as `@hillbombcreations/site-loader` (read its version from `packages/site-loader/package.json`; it runs inside VR_Secure_API's `instantiateTemplateWorker` in prod, pinned exactly; this skill owns it, see the site-loader section), exposing `instantiateBlueprint` so the portal TEMPLATE PICKER can instantiate published blueprints.

## /migrate pipeline + gates

`crawl` (`commands/crawl.js <url> --max-pages=120 --deep`, deep = a second Playwright engine in `src/capture/deepCapture.js`; probe-discovered dead-404 routes dropped by `src/capture/deadPageFilter.js`; Elementor body recovery via `collectTopLevelBlocks` in `src/capture/extractInPage.js`; Shopify catalog facets auto-enriched into `capture.commerce`, backfillable via `commands/enrich-commerce.js`) → `ingest` agent → `collections` + `integrations` agents (parallel; then the deterministic `commands/build-derived-collections.js` step, e.g. `buildHomeComparisonRows`) → `site` agent (LAST, binds only to keys collections emitted) → `commands/assemble-blueprint.js --gap-policy` → `commands/preview-bundle.js` + `serve-preview.js` → **audit** → Studio validation → `commands/load.js` (**user-gated cutover**). `captures/<domain>/` is gitignored and fully regenerable.

`/migrate <url>` runs it end to end with **3 human approval gates**: **Gate 1** pre-flight (URL + crawl scope, brand name, drives the `<key>.vivreal.io` subdomain, rendered brand, AND the Templates branch name, target group, gap policy, AND kit selection: `commands/select-kit.js` matches the vertical to an authored kit and writes `kit.json`, styling only, client brand always wins). **Gate 2** pre-creation (blueprint summary + per-page parity diff + screenshots; zero data/structure defects expected). **Gate 3** cutover (dispatches the `cutover` agent against production).

**Cutover:** default target is a **provisioned prospect-owned demo account** (VR_Main_API `provisionDemoAccount.js`, same brand name as assemble), deploys noindex; pass `--live` ONLY at genuine go-live. `load.js --deploy` triggers the Deploy-Site Step Function via `POST /api/deploySite` (blank-template sites don't auto-deploy) and the `/api/revalidate` cache webhook; resume-safe via `load-state.json`. The loader drops pages bound only to zero-object collections (`convertBlocks` in the site-loader package). **Closing gate (MANDATORY after every deploy): `commands/verify-live.js`**, an HTTP-status sweep is NOT enough (Next streams a 200 shell and can `notFound()` mid-stream); it browser-drives every blueprint page checking hydrated-404 swap, a hydrated-content floor, TRUE-pixel image sharpness (density-corrected, re-decoded per `currentSrc`), and same-origin favicon links. **Hardened further post-firstmigration.example**, the firstmigration.example migration cutover (below) surfaced gaps this gate now closes; treat `verify-live.js` as the authoritative post-deploy check, not a formality.

**The firstmigration.example cutover**, a real `/migrate` run that exercised the pipeline end to end and fed fixes back in: closed parity-audit gaps (4A/4B live-DOM parity), Studio-editability-gate fixes (stage 11b), and capture/crawl fixes upstream in `src/capture/`. Treat it as evidence the audit gates catch real regressions, not a checklist step to skim.

## /template pipeline (identity kits)

`/template <exemplar-url>`: **scout → design gate → build (Round A/B) → validate**, with its own user gates. **GATE 1**, the `kit-designer` agent live-scouts the exemplar, writes the design brief (HANDOFF doc) + question set. **Round A**, kit authoring (persona + theme + chrome + home); **Round B**, the page walk, each exemplar page authored in its grammar (section order and words stay the kit's own). **Validate**, `commands/{confirm-site,confirm-page,exemplar-diff,rebrand-capture,harden-demo,distill-kit}.js`; the `page-confirm` agent rates every section MATCH / ADAPTATION / SURPLUS / DEFECT. **GATE 3** ships only when the **kit quota** is met: Nav 1 · Header-hero variant 1 · Landing structured components ≥3 · Motion preset 1 · Page type (new `format`) ≥1 (knobs don't count). Kits live in `kits/authored/*.json`; three bakery kits shipped there (Levain, Poilâne/"Old Mill Bakehouse", Ansel). Musician template #1 **"poster-pop"** (MOTEL SATURN) shipped as a FOURTH industry template, but it was NOT distilled into `kits/authored/` (evidence it exists: renderer 1.40/1.41, site-loader 0.2.3/0.2.4, `docs/projects/industry-example-site-templates/HANDOFF-MUSICIAN-1.md` + `HANDOFF-MUSICIAN-PAGES.md`, `publish-out/musician-woozy`), note the asymmetry so nobody hunts for a musician JSON kit. **RESALE-1 "Marlowe & Kept"** (resale/thrift vertical) shipped alongside renderer 1.50.0 and the site-loader 0.3.x line, the fifth industry template; ride the same release-train discipline (renderer publish → site-loader pin bump → capability manifest regen) before treating it as fleet-safe. `component-builder` is the aesthetic-matching component authority: TEMPLATE mode builds net-new in the renderer repo, MIGRATION mode reuses best-fit only. Publishing: `commands/publish-template.js` + `infra/site-templates-bucket.yaml` (S3), the portal picker then instantiates via `instantiateBlueprint`.

**Studio-editability gate (template-flow stages 5b + 11b).** Stage **5b, Studio registration**: the `studio-registrar` agent handles portal-side palette/editor/whitelist registration for each kit surface. Stage **11b, STUDIO GATE**: `commands/confirm-studio.js` (page coverage · editor-stub scan · no-edit Save-All roundtrip) → STUDIO PASS, then the `studio-confirm` agent runs the agent edit walk with a classification ledger, verifying every kit surface is editable in the real portal Studio. Supporting modules `src/studio/{mintCookies,saveRoundtrip,siteValuesMerge,surfaceInventory}.js`; tests `tests/studio-save-roundtrip.test.js` + `tests/studio-sitevalues-save.test.js`; `commands/mint-studio-cookies.js` is now a thin wrapper over `src/studio/mintCookies.js`. Walk-2 benign save materializations are pinned as non-FAIL in `saveRoundtrip`.

**Vivreal Content template-site rule** (docs/template-flow.md): every site instantiated from a template (validation, demo, smoke, showcase) is created on the **Vivreal Content** group, groupName "Vivreal Content", key `vivrealcontent`, `_id <look up by key vivrealcontent>`.

**Release train** (template-flow.md §6b + `docs/fleet-release-train.md`): any kit that shipped renderer/site-loader surface rides renderer publish → capability manifest regen FROM THE PUBLISHED TARBALL (`npm run gen-capabilities`; a dev dist stamps a false version) → site-loader version bump → manual `npm publish` of site-loader (there is no CI here) → VR_Secure_API pins the new site-loader EXACTLY with a tripwire test and backports it (Secure #322 took 0.7.1 into v2.20.1). Prove a publish with `npm view @hillbombcreations/site-loader@<v>` (gitHead, shasum) against the tarball, not with the publish command's exit code.

**Kit gates (2026-10):** `npm run lift-gate:all` clears every authored kit (15 of 15 on 2026-10-03/04), `npm test` is `scripts/test-all.js` over the root and the site-loader suites, and the portal's `kit:validate` proves a kit is EDITABLE in Studio, not just renderable. ## v7 to v7.2 kit and loader rules (migrator master at `afdb29f`)

- **Kit sample content holds no real phone, domain or brand anywhere,** including inside base64 data, `data:` URIs, percent-encoded strings and PDF streams: the kit guard decodes them, because a raw-string guard once missed dozens of phone numbers inside a menu PDF. A kit whose seedable copy names its own brand or town is refused (S9-D5). Brand-named contact headings become neutral, empty link fields are switched off rather than left dead, and a map embed with no address is removed.
- **One brand name across a kit's data and its copy.**
- **Kit copy never promises a confirmation email (v7.2).** Site sign-ups are one step, so "check your inbox to confirm" is gone from the kits.
- **A kit's sample time zones only reach demo sites.** VR_Secure_API strips page, opening-hours and section zones at a customer instantiation (`scrubKitZones`), so the customer's business zone governs. Do not rely on a kit zone for anything a customer sees.
- **site-loader's Repeats help** names the word the site repeats on and says repeats stop after the end date if one is set, matching the renderer's repeat-until rule. The prod worker runs the version VR_Secure_API's deployed tag pins (v2.22.6 pins this release); between releases that pin can lag master.
- **An empty binding can still draw its heading over an empty body** (a layout declaring `nullOnEmpty: false` keeps its section when the list is empty), so set `showHeader: false` on a kit binding that may seed nothing.
- **Kit sample dates are seeded on or after the seed date** (site-loader, S9-D2), so a new site never opens with an events list that is already over.

## PARITY STANDARD (the pass/fail bar)

**/migrate: 1:1 parity with the live site on DATA and STRUCTURE**, every page, section, item, field, media asset, link, and nav entry present, nothing invented. **Gaps are DEFECTS to resolve, not residuals to accept.** Styling is the ONE allowed divergence (Vivreal's design system may look *better*). **/template inverts it:** the same 1:1 discipline applied to DESIGN/LAYOUT, content is placeholder and the brand fictional by design. Never declare a page done from the crawl alone.

## Audit passes + the post-deploy gate

- **4A, live-DOM parity sweep (MANDATORY, first):** for EVERY page, Playwright-load the LIVE site, scroll top-to-bottom, extract a fingerprint (headings, `<video>` + CSS `background-image` srcs, iframes, image/form counts, nav, every external href), diff against the blueprint. Any delta is a defect, recover from the live DOM and re-dispatch the owning agent.
- **4B, local render vs live:** serve-preview shim on `127.0.0.1:8799` + Templates dev server (`dev:linked` for unpublished renderer work), screenshots at 1280 + 375 for home, a nested page, and each content-type page, compared against live. **`dev:linked` leaves a dev build of the renderer overlaid on Templates' installed package and never reverts it, and the version, `npm ls` and the lockfile all keep reading authentic, so a parity screenshot taken afterwards is evidence about unpublished renderer code, not about what a customer site will render (measured 2026-09-30: it went five days undetected and produced three wrong conclusions).** Revert with `node ../vivreal-site-renderer/scripts/dev-unlink.js` and confirm INSTALL with `node ../vivreal-site-renderer/scripts/dev-status.js` before you sign off a parity pass.
- **C, post-deploy live gate:** `verify-live.js` (above), run by the cutover agent after every load/cutover deploy.

## Gap policy (block / best-fit / partial)

- **`block`**, the Gate 1 default: assembly HALTS (exit 2) on any unresolved gap. The parity-run setting.
- **`best-fit`**, writes the blueprint with gaps recorded but exits 0 (partial-land); allowed ONLY with an explicit, per-gap user waiver. Never report best-fit coverage as faithful render. At assemble, `partial` is a friendly ALIAS for best-fit.
- `load.js` takes its own `--gap-policy block|partial` for seeding what's resolvable.

## Key heuristics (hard-won, verified live)

- **Static-crawl blind spots:** the crawl captures initial HTML, not the runtime DOM, it misses CSS-`background-image` media (hero videos, bio photos), lazy galleries, and JS-wired `href`s (press/gift-card/reserve/nav links). `--deep` recovers most; the 4A sweep is the backstop.
- **Platform-aware deep extraction:** detect the source platform and prefer its structured API over card scraping, WooCommerce `/wp-json/wc/store/v1/products`, Shopify `/products.json` (+ `capture.commerce` facets: variant sizes, option groups), Squarespace `?format=json`. Model `description` + `options` + `gallery` from day one; HTML-entity-decode names before matching.
- **Slug depth ≤ 2:** Templates routes only `[slug]` and `[slug]/[itemId]`, a 3+ segment source path preserved as a slug hard-404s even though it seeds fine. Flatten to a routable leaf and rewrite every nav/footer href.
- **⚠ Deep-slug 301s are applied by NOTHING** (`docs/seo-redirects-at-cutover.md` + the README banner): the blueprint's 301 map for slugs flattened past `MAX_SLUG_DEPTH` is computed but no component applies it, old URLs 404 once a site goes live. BLOCKING for the first cutover of any site with a non-empty redirects array.
- **Preview media descriptors carry a `name`** (`commands/serve-preview.js`), unblocks required-image object saves in the Studio harness (defect D-1).
- **`verify-live.js` browser-boundary rule:** it destructures `PROSE_BLOB_CHARS`/`SHARE` into the `page.evaluate` callback, closure vars don't cross the browser boundary; keep constants passed explicitly.
- **WordPress `-WxH` thumbnail normalization:** `src/capture/imageUrl.js` strips trailing `-WxH` from `/wp-content/uploads/` image URLs (sized thumbnails 404; originals always exist).
- **Probe-guessed routes lie on WordPress:** guessed paths (`/menu`, `/about`, …) resolve to the theme's 404 template with a 200, `deadPageFilter.js` drops them (probe-discovered pages ONLY; linked/sitemapped pages are never touched).
