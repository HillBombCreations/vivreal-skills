Maps to `NEXT_PUBLIC_SECURE_URL`. Express + serverless-express on Lambda (Node 20, arm64), JavaScript, MongoDB, Cognito JWT, SAM. ## Architecture — 13 Lambdas (main SAM stack)

`userAndAuth` (profile switch, email, logout — email update now fails closed on Cognito ListUsers truncation and rejects an email held by another user), `billingAndSubscription` (Stripe checkout/portal/webhooks/preflight/overage), `createAndJoinGroup`, `createSites` (templates + template instantiation, Route53, domain purchase/transfer, Step Functions, WebSockets — most files + AWS integrations; 2048MB/60s since the instantiation work), `getGroupInformation` (read-only + admin attribution + `GET /api/analytics/site/traffic`; serializes `overQuotaSinceCancellation` + derived `usage.{cdn,api,agent}.{pctOfQuota,nearQuota,overQuota}`), `updateGroup` (members, roles, API keys, integrations, overage toggle, featureFlags, `refreshSocialProfile`), `agent` (`src/agent/` — AI agent orchestrator + tool layer), `webhookDelivery` (SQS consumer, HMAC-signed outbound webhooks), `analyticsSnapshot` (EventBridge `cron(0 6 * * ? *)`), `squareTokenRefresh` (daily sweep cron), `squareRefreshOne` (invoke-only — cross-stack target for VR_Client_API's `squareTokenGuard`), `instantiateTemplateWorker` (**no HTTP route**; direct-invoked by createSites' `instantiateTemplate` via the `INSTANTIATE_TEMPLATE_WORKER_LAMBDA` env; 1024MB/900s; own DLQ + `InstantiateTemplateWorkerErrorsAlarm`), `instantiateTemplateWorkerDlqConsumer` (NEW — `InstantiateTemplateWorkerDlqConsumerFunction`; consumes the worker's OnFailure DLQ; own webpack entry + SAM function; marks hard-killed final-attempt sites failed from the destination envelope; partial-batch semantics, poison messages dropped). **The websocket stack (`websocket/template.yaml`) is separate — never count its 4 functions in this roster**; `allRoutes.packaged.yaml` is a stale CI artifact — never count from it. 4 of 13 have WebSocket integration (agent, createAndJoinGroup, createSites, updateGroup). Shared: `encryptionUtils.js` (AES-256-GCM for integration creds), `handleHBRoutes.js`, `socket.js`, `auditLog.js`, `deriveDbKey.js`.

## Square P2 (token lifecycle + provider mutex)

- `squareTokenRefresh`: daily `rate(24 hours)` sweep refreshing tokens <14 days from Square's 30-day hard expiry; 36h dead-man + Errors≥1 alarms.
- `squareRefreshOne`: no route/schedule; resource-based `AWS::Lambda::Permission` for VR_Client_API's role (`SquareRefreshOneInvokerRoleArn`) — synchronous single-account refresh.
- **D4 payments-provider mutex**: one active payments provider per group — `updateIntegrations.js` + `oauthService.js:storeTokens` throw `PaymentsProviderAlreadyActive`.
- Revoke-on-disconnect via `src/shared/square/revokeSquareToken.js`. The `featureFlags.squareStorefront` gate is GONE platform-wide (flag retired from `ALLOWED_FLAGS`). `PAYMENTS_WRITE` added to the OAuth scope list — CreatePaymentLink 403s `INSUFFICIENT_SCOPES` without it.
- **Production cutover 2026-07-28**: SSM `/vivreal/prod/shared/square-env` = `production`. Existing sandbox-connected accounts are dead against the production app — the refresh sweep marks them expired; merchants must re-OAuth.

## Tier quotas — v3.1.0 sentinel scheme + AI capability flags + AI agent

Quotas live in **`@hillbombcreations/tier-quotas` v3.1.0** — **sentinel scheme: -1 = unlimited, 0 = no access (fail-closed), >0 = cap**, read via helpers `isUnlimited(<0)`, `hasAccess(!==0)`, `getEffectiveLimit`; the old `isUnlimitedQuota(0)==unlimited` inversion is GONE. `agentActions`: free 0 (**now truly denies** — was a dead gate, same fix for free `webhooks: 0`), basic 50, pro 500, **proplus 500 (cut from 5,000 in v2.3.0, retained through v3.1.0)**, enterprise -1. v3.1.0 adds the binary capability flags `aiSiteEditing` + `aiComponentGen` in `TIER_FLAGS` (free/basic false; pro gains `aiSiteEditing` only; proplus + enterprise gain both; `lowestTierWithFlag()` derives the required tier) — first consumer is the agent's `tools/policy.js`, which derives per-tool `requiredTier` from `TIER_FLAGS` instead of hardcoding. **W6 read-flip:** the 6 tier-driven fields (entries/seats/sites/apiCalls/cdnBytes/agentActions) read live from `getTierQuotas(group.tier)` at every gate (`joinGroup`, `acceptRequest`, agent metering, `getAgentContext`, `instantiateTemplate`, `createSiteCollectionData`, `createSiteWithExistingCollections`, `getGroupInfo` v1+legacy, `updateEmail` serializers) — `updateGroupTier` + `handleSubscriptionEnd` STOPPED writing them, and the per-group `agentUsage.quota` override is GONE from `checkAgentQuota` (`src/agent/services/metering.js`): past-quota agent use requires `overageBilling.enabled` and hard-stops at the spending cap. `mediaUsage.quota` is admin-override-only (W7). The `aiActionsEnabled` toggle requires `hasAccess(agentActions)` → new `FeatureNotAvailableOnTier` error. Allowlist gate + prompt caching + monthly usage reset live in `src/agent/`.

## Multi-tenant routing — `dbKey` (NOT `key`)

**Secure reads `req.query.dbKey`** — CMS reads `key`. The portal proxy must set `dbKey` explicitly for Secure routes. `dynamicDb.js` pools per-tenant connections (`maxPoolSize=3`). mainDb `Vivreal` holds group metadata. **Never filter mainDb by `groupName`** — use `{ _id: groupID }` / `{ key: dbKey }`.

## Adding a route — 7 steps (step 7 = the 502 trap)

1. `services/foo.js` → 2. `services/index.js` → 3. `api/controllers/foo.js` (set `req.resData`) → 4. `api/controllers/index.js` → 5. `scripts/validators.js` (Joi) → 6. `api/index.js` (`handleHBRoutes`) → **7. `cloudformation/<lambda>.yaml` API Gateway event**.

**Step 7 is a hard rule.** Secure (like CMS + Client) registers **one explicit API Gateway event per route** — there is **no catch-all `{proxy+}` integration**. An Express route the gateway has no event for is unreachable: the request falls through and fails — **502** post-deploy here (CMS surfaces the same miss as a 403; Client rejects it at the edge). Always add the event in the `cloudformation/` fragment; `cloudYamls/allRoutes.yaml` is generated by `scripts/merge-template.js` — never edit it directly. (Cross-repo rule + why Main API is exempt: `vivreal-lambda` deploy reference + `vivreal-auth-architecture`.)

## Billing specifics

- **Downgrade preflight** (`GET /api/billing/preflightDowngrade`) — recounts `collection_objects` + `webhooks` via tenant connection, compares to target tier quotas, returns `{ ok, violations[], currentTier, targetTier }`. Downgrade to a 0-access target (e.g. free's `webhooks`/`agentActions` 0) is now a preflight violation. Re-used by `createCheckoutSession` as a defence-in-depth gate (400 with violations on reject). Opportunistically heals `entries.totalSize` drift.
- **Cancellation** (`handleSubscriptionEnd.js`) — demotes to `free` (it no longer writes the 6 tier-driven quota fields — they derive live from the tier), sets `frozen:true` + persists `overQuotaSinceCancellation {violations, setAt}` when over-limit; `getGroupInfo` serializes it → drives the portal frozen/over-quota banner. Webhook-order safe: lookup by `stripeSubscriptionID` misses (no-op) when cancellation is the side-effect of an in-progress tier change.
- **Stripe portal lockdown** — optional `STRIPE_PORTAL_CONFIGURATION_ID` disables `subscription_update` so tier changes route through the preflight-gated Manage Plan page. Bootstrap is a manual one-time script.
- **Overage billing** — new paid subs **auto-enroll** `overageBilling.enabled` + the tier default spending cap (`DEFAULT_SPENDING_CAP`; grandfathered if the prior tier was overage-eligible, enterprise excluded); toggle via NEW **`PUT /api/group/overageBilling`** (`toggleOverageBilling.js`, native-driver persist). `createCheckoutSession` discloses overage + cap in Stripe `custom_text`. `handleInvoiceCreated.js` adds Stripe invoice items at the tier-quotas `OVERAGE_RATES` (CDN $0.50/GB, API $0.005/call, agent $0.05/action); the `overageBilling.lastInvoice` snapshot persists via the native driver, and a **deterministic per-(invoice,bucket) Stripe idempotency key** stops duplicate charges on `invoice.created` retries; fails safe (undercharge not overcharge). The old "`overageBilling` + `stripeSubscriptionID` UNDECLARED in strict `groupSchema`" gotcha is **RESOLVED by schemas 1.27.0**, which declares `dbKey`, `stripeSubscriptionID`, `subscriptionStatus`, `subscriptionCadence`, `currentPeriodEnd`, `overageBilling{enabled,spendingCap,lastInvoice}`, `scheduledTierChange`, `cancellation`, `pauseCollection`, `retentionDiscount`. The native-driver write is retained DELIBERATELY (`spendingCap` is Mixed with dynamic `bucketCaps.<bucket>` keys), not because of stripping. `featureFlags` is declared in schemas 1.29.0 (strict:false sub-schema, only `aiActionsEnabled` declared), though `updateFeatureFlags.js` still writes via the native driver.
- **Cancel flow + retention (Phase 3)** — `billingAndSubscription/services/subscription/{cancelSubscription,pauseSubscription,reactivateSubscription,applyRetentionDiscount}.js`, gated by `requireGroupBillingRole.js`; routes `POST /api/billing/{cancelSubscription,pauseSubscription,reactivateSubscription,applyRetentionDiscount}` + `releaseScheduledChange`. Cancellation is **period-end, never immediate** (`cancel_at_period_end` + `cancellation.{requestedAt,effectiveAt,reason,feedback}`; demotion happens in `handleSubscriptionEnd`). **Pause does NOT set `frozen`** (D9 — `frozen` is enforced by Client API's `frozenCheck` and would take the public site dark); CMS blocks writes on a future `pauseCollection.resumesAt` (`GroupPaused` 403). One pause per 12 months, anchored on `pauseCollection.lastPausedAt`. Retention: coupon `retention_save_30_3mo` (30% off, repeating 3 months), `RETENTION_COUPON_ID` via SSM `/vivreal/prod/shared/stripe-retention-coupon-id`, once per group guarded on `retentionDiscount.appliedAt` (NOT Stripe's discount list — that only reports currently-applied discounts); deliberately no `max_redemptions`. NY GBL 527-a imposes an advance-notice obligation before any price change.
