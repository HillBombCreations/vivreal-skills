# Dispatch template

From the owner-approved 2026-10-06 template plus audit-3 2.7, and field 9 from the 2026-11-04 skills batch. Every dispatch carries all nine.

Every dispatch: (1) ONE repository per coder or portal-coder dispatch; several repos means several dispatches. (2) The base or head SHA, pinned (`origin/main@<sha>`), and the `model` from the live values printed at session start (owner rule P-model). (3) The spec file path when one exists. (4) The mode, for portal-coder. (5) The exact commands it may run and the test scope; every WSL step in them starts by changing into the worktree inside one quoted command (`wsl bash -c 'cd /mnt/<drive>/<clones>/_wt/<worktree> && <command>'`), because a bare `wsl` call runs in whatever folder the shell is in, often an owner's own checkout. (6) Full scope and authority in the first prompt; a GO is quoted verbatim with name, time and source: `GO: "<exact words>" from <Justin|Hunter>, <ISO time>, <source>`. The name is the co-owner who gave it (ask "which co-owner" in the same question; never infer it from an account email or git config), the time is exact (`date -u +%Y-%m-%dT%H:%M:%SZ` run right after the answer, never "about 17:25Z"), and it sits in the FIRST prompt of a fresh dispatch; the release engineer refuses anything less, which cost two round trips on 2026-11-04. (7) Verified premises only: read the deployed validator or release line, not main. (8) Report at most 250 words, ending with any `Needs:` line. (9) Done means pushed, with a PR URL in the report (vivreal-skills: committed on a local branch, one PR per batch, pushed only when ready to merge, P-skills-push-after-review) (or the pushed head SHA in a no-PR mode). No skill or review runs as the last step.

Two traps around a dispatch. Preparing is not dispatching: after an environment readiness report, launch the agent that uses it in the same turn. Never tell a coder to "consult an expert": that consumes the coder's own task; name the knowledge skill it should load instead.
